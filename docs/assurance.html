Vordr / verification map

Evidence, with its limits in view.

A guide to how the checks fit together—not a live test result or a security certification.

No independent external security review is recorded in the repository. Passing tests does not establish the absence of vulnerabilities.

One gate, six stages

The driver runs these stages in order. It switches build variants for diagnostic probes and restores a normal executable before packaging.

  1. 01 / FAULT INJECTION

    Exercise runtime checks

    Trigger stack, heap, bounds, indirect-call, and import-table violations. Check that the test process terminates.

  2. 02 / STRICT BUILD

    Check source patterns

    Run eight Python checkers, then assemble, compile resources, and link. Python must be present for the source checks.

  3. 03 / SELF-TESTS

    Check known answers

    Exercise fixed cryptographic and policy inputs. Startup also runs a fail-closed self-test gate.

  4. 04 / ROUND-TRIPS

    Exercise data lifetimes

    Test records, attachments, imports, saves, cleanup, and bounded malformed inputs in a diagnostic build.

  5. 05 / CRYPTO CROSS-CHECK

    Compare outputs

    Compare with Python calculations and published vectors. Argon2 uses a published vector, not a second full implementation.

  6. 06 / INSTALLER

    Inspect package behavior

    Build and cost the MSI after restoring a normal build. Real installation, upgrade, and uninstall still need separate tests.

A successful summary can include skipped checks. Review the logs for missing Python, installer tooling, or an interactive desktop.

Encryption is one boundary, not the whole lifecycle

Unlocking makes data usable. Copying or previewing it then crosses into systems that Vordr does not fully control.

Read a passing result precisely

What it can demonstrate

  • A fixed input produced the expected output.
  • A selected fault triggered a runtime check.
  • A synthetic save or import preserved the tested data.
  • A particular executable matches a recorded hash.

What it does not establish

  • All inputs and failure paths are safe.
  • All sensitive memory is locked or wiped after every crash.
  • Cryptographic output checks prove side-channel resistance.
  • A matching source build contains no vulnerabilities.

Reproduce on a safe test machine

The full driver stops running Vordr processes and replaces build outputs. Use synthetic data in a dedicated checkout or VM.

tests\run_all.cmd

python tests\verify_crypto.py --exe bin\vordr.exe

Record the commit, toolchain, commands, logs, and any skips. Read the development guide before running the gate.
