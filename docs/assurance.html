Vordr / verification map

Earned trust, with its limits in view.

How Vordr's architecture, independent reference readers, and six-stage verification gate fit together—an offline engineering reference, not a live dashboard or external certification.

Every claim is backed by runnable checks in this repository, while no external third-party audit is recorded here. Passing deterministic tests bounds known failure classes without proving the absence of all defects.

One gate, six stages

tests\run_all.cmd executes these stages in sequence, using isolated HKCU test hives for diagnostic probes and restoring a clean release executable before packaging.

  1. 01 / FAULT INJECTION

    Verify fail-fast & containment

    Trigger stack canary, TLS shadow-stack (top and ancestor-skip), landing-pad, heap-tag, bounds, arithmetic, crash-reentrancy, System32 DLL load, and read-only IAT guards via tests\redteam.py.

  2. 02 / STRICT BUILD

    Enforce static & PE invariants

    Run ten Python assembly, Win64 ABI, resource, and doc analyzers gated by coverage floors (floors.py), link with ASLR/DEP/HEVA/CET, and verify DependentLoadFlags = 0x0800 (pe_normalise.py). Fails closed if Python is missing.

  3. 03 / SELF-TESTS

    Run 23 startup KAT suites

    Verify FIPS-197, SP 800-38A/D, RFC 9106 Argon2id, RFC 7693 BLAKE2b, RFC 6238 TOTP, register/XMM scrubbing, CPU/XCR0 gates, and URL/filename/JSON sanitizers. Every normal launch runs this gate fail-closed.

  4. 04 / ROUND-TRIPS & GUI

    Exercise formats, fuzzers & UI

    Run 35+ container, parser-fuzz, policy, TPM, and persistence probes, a zero-shared-code Python vault reader (verify_vault.py), frozen v0.2.3 fixtures, and a 91-check isolated Win32 GUI suite (guitest.ps1).

  5. 05 / CRYPTO DIFFERENTIAL

    Cross-check 83 vectors

    Compare 58 primitive outputs from katreport against independent Python calculations and 25 published FIPS/NIST/RFC test vectors via tests\verify_crypto.py.

  6. 06 / INSTALLER

    Cost & verify the MSI

    Build the MSI around the restored release binary and cost its tables via Windows Installer COM: 16 policy rows, numeric LaunchCondition guards, SDDL permissions, and downgrade prevention (NEWERVERSIONDETECTED).

Strict builds require Python and fail closed without it. Inspect the stage log if makecab.exe or an interactive desktop is unavailable on a headless runner.

Read passing evidence with scientific precision

What the suite demonstrates

  • Independent Python readers agree byte-for-byte with Vordr's wire format and cryptographic outputs.
  • Every deliberate memory, ABI, frame, or loader fault triggers its dedicated fail-fast or containment path.
  • Two clean release strict builds produce identical SHA-256 binaries with ASLR, DEP, HEVA, and CET intact.
  • Policy locks, modal auto-lock, attachment caps, and rollback counters hold under automated CLI and GUI probes.

What remains outside automated proof

  • Bounded fuzzing and fixed KATs do not prove safety over all possible inputs.
  • User-mode VirtualLock and zeroing cannot block a hostile kernel, admin debugger, or unencrypted hibernation file.
  • Functional output vectors do not prove microarchitectural side-channel immunity across all CPUs.
  • COM table costing does not replace live VM upgrade and uninstall testing.

Reproduce on an isolated test machine

tests\run_all.cmd terminates running vordr.exe processes and overwrites bin\. Run it in a clean checkout or VM with synthetic data.

tests\run_all.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify_repro.ps1

Record the commit hash, MSVC/SDK versions, full stage logs, and any environment skips. Read the development guide before running the gate.
